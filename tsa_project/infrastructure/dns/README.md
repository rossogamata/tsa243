# DNS — ns1.tsa243.lab

**VM:** `ns1.tsa243.lab` · `192.168.177.10`  
**Сервіс:** BIND9  
**Зона:** `tsa243.lab`

---

## Що керує викладач

- Зона `tsa243.lab` та зворотня зона `177.168.192.in-addr.arpa`
- A-записи для спільних VM (gateway, mail, proxy, mon)
- Налаштування рекурсії та forwarders (8.8.8.8)

## Що робить кожен курсант

1. Підключається до `ns1` по SSH з ключем
2. Додає свій A-запис у зону `tsa243.lab`:
   ```
   surname    IN  A  192.168.177.1XX
   ```
3. Перевіряє конфіг: `sudo named-checkzone tsa243.lab /etc/bind/db.tsa243.lab`
4. Перезапускає зону: `sudo rndc reload tsa243.lab`
5. Перевіряє з будь-якої VM: `dig surname.tsa243.lab @192.168.177.10`

## Навчальний момент

Якщо двоє курсантів одночасно редагують зонний файл — виникає конфлікт.
Це природній момент для пояснення: **навіщо потрібен version control для конфігів**.
На наступному курсі цей файл буде в Ansible і застосовуватиметься через CI/CD.
