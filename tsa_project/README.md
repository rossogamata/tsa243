# TSA Project — Навчальна Production Інфраструктура

> **Дисципліна:** Технології системного адміністрування  
> **Група:** ТСА-243 · 29 курсантів  
> **Середовище:** Proxmox VE / Ubuntu Server 24.04 LTS  
> **Домен:** `tsa243.lab`

---

## Концепція

Кожен курсант — системний адміністратор **власного ізольованого середовища**.
Не одна спільна VM, а повноцінний стек сервісів у власній підмережі.

Викладач розгортає **центральне середовище** яке інтегрує всіх курсантів:
- DNS-ієрархія: делегування субдоменів на сервери курсантів
- SMTP relay: пошта курсантів іде через центральний сервер
- Reverse proxy: єдина точка входу, трафік розподіляється по середовищах

Помилки ізольовані — якщо курсант зламав свій DNS, страждає тільки він.
Але архітектура реальна — сервіси курсантів інтегровані через сервіси викладача.

## Адресація

**Схема:** `11.203.{№курсанта}.0/25`

| Середовище | Підмережа | Хто |
|------------|-----------|-----|
| Викладач | `11.203.0.0/25` | Центральні сервіси, точка інтеграції |
| Курсант 1 | `11.203.1.0/25` | Повний стек сервісів |
| Курсант 2 | `11.203.2.0/25` | Повний стек сервісів |
| … | … | … |
| Курсант 29 | `11.203.29.0/25` | Повний стек сервісів |

Кожен /25 → 126 адрес. Достатньо для всіх VM і backend-сервісів з запасом.

## Потік трафіку

```
Клієнт: http://surname.tsa243.lab
         │
         ▼ DNS lookup
    ns1.tsa243.lab (11.203.0.10)
    "surname.tsa243.lab делеговано → 11.203.X.10"
         │
         ▼ DNS lookup до курсанта
    ns1.surname.tsa243.lab (11.203.X.10)
    "surname.tsa243.lab → 11.203.0.12"  ← вказує на proxy викладача
         │
         ▼ HTTP
    Nginx викладача (11.203.0.12)
    vhost: surname.tsa243.lab → upstream 11.203.X.12
         │
         ▼
    Nginx курсанта (11.203.X.12)
         │
         ▼
    HAProxy курсанта (11.203.X.13)
         │
         ├─▶ backend-01 (11.203.X.30)
         └─▶ backend-02 (11.203.X.31)
```

## Потік пошти

```
Курсант відправляє: surname@tsa243.lab
         │
         ▼
    Postfix курсанта (11.203.X.11)
    relayhost = 11.203.0.11
         │
         ▼
    SMTP relay викладача (11.203.0.11)
         │
         ▼
    Destination MX або інший курсант
```

## DNS-ієрархія

```
tsa243.lab  (авторитативний: ns1.tsa243.lab · 11.203.0.10)
│
├── NS-delegation → surname1.tsa243.lab @ 11.203.1.10
├── NS-delegation → surname2.tsa243.lab @ 11.203.2.10
└── ...

surname1.tsa243.lab  (авторитативний: ns1.surname1.tsa243.lab · 11.203.1.10)
├── A  surname1.tsa243.lab       → 11.203.0.12  (proxy викладача!)
├── A  ns1.surname1.tsa243.lab   → 11.203.1.10
├── A  mail.surname1.tsa243.lab  → 11.203.1.11
├── A  www.surname1.tsa243.lab   → 11.203.0.12
└── MX surname1.tsa243.lab       → mail.surname1.tsa243.lab
```

### Структура гілок

```
main  ← викладач: матеріали занять, еталонні конфіги, шаблони
├── surname1
├── surname2
```

### Захист практичних — один PR на заняття

```
1. Виконати роботу на VM
2. Задокументувати в cadets/surname/reports/lessonX_Y.md
3. git commit -m "lessonX_Y: короткий опис"
4. git push origin surname
5. Відкрити PR: surname → main
6. Approve викладача = залік
```

## Чому саме такий підхід

| Ізольовані лаби | TSA Project |
|-----------------|-------------|
| Один сервіс за раз | Повний стек, реальні залежності |
| Помилки не мають наслідків | Зламав DNS — твої сервіси недоступні |
| Немає архітектурного мислення | Треба розуміти як сервіси пов'язані |
| Немає досвіду multi-tier | Nginx → HAProxy → backend = реальний патерн |
| Документація як формальність | PR-звіт = умова отримання заліку |

## Міст до наступного курсу

**Поточний курс:** все вручну, `repo` = щоденник.  
**Наступний курс (Docker / Ansible / Terraform / CI-CD):** той самий стек,
але розгортається кодом. Курсанти автоматизують **інфраструктуру яку вже знають руками**.
