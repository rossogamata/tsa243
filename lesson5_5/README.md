## Чому Proxmox для цього заняття

Proxmox VE надає ізольоване мережеве середовище з керованими мережевими мостами (`vmbr`), що дозволяє:
- Створювати кілька VM в одній мережі без фізичного обладнання
- Легко додавати/видаляти мережеві інтерфейси до VM через GUI
- Моделювати реальну топологію: сервер ↔ клієнт через внутрішню мережу
- Спостерігати мережевий трафік між VM у реальному часі

**Топологія заняття (мережа 192.168.177.0/24 на мосту `vmbr0`):**

```
[Proxmox Host]
      │
   vmbr0  (192.168.177.0/24)
    ┌──┴──────────────────────┐
    │                         │
[VM1: server]          [VM2: client]
192.168.177.101        192.168.177.102
eth0 (enp0s18)         eth0 (enp0s18)
```

> VM1 і VM2 — Ubuntu Server 24.04. Обидві VM підключені до одного моста `vmbr0`.
> Перед початком роботи з'ясуйте свою IP-адресу: `ip a show eth0`
>
> **Приклад реального виводу у Proxmox VM:**
> ```
> 2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP
>     link/ether bc:24:11:76:cb:f9 brd ff:ff:ff:ff:ff:ff
>     altname enp0s18
>     inet 192.168.177.17/24 metric 100 brd 192.168.177.255 scope global dynamic eth0
> ```
> Інтерфейс може мати альтернативне ім'я `enp0s18` — це те саме, що `eth0`.

### Типова проблема: обидві VM отримали однакову IP-адресу

При клонуванні VM у Proxmox обидві машини можуть отримати однакову адресу від DHCP. Причина — DHCP-сервер ідентифікує клієнта за `machine-id` або MAC-адресою, а у клонованих VM вони збігаються.

**Діагностика** (виконати на обох VM):

```bash
# Порівняти machine-id
cat /etc/machine-id

# Порівняти MAC-адреси
ip link show eth0 | grep "link/ether"
```

**Якщо збігається `machine-id`** — скинути і перегенерувати:

```bash
sudo truncate -s 0 /etc/machine-id
sudo systemd-machine-id-setup
sudo reboot
```

**Якщо збігаються MAC-адреси** — виправити у Proxmox GUI:
`Hardware → Network Device → Edit → MAC address → Generate` (на одній з VM), потім перезавантажити її.

Після перезавантаження DHCP-сервер видасть різні адреси. Проблема повністю зникає після налаштування статичних адрес через Netplan (розділ 1.3).

## 1. Мережеві налаштування у Linux

### 1.1 Огляд мережевого стеку Linux

У сучасних дистрибутивах Linux мережевий стек організовано так:

| Рівень | Компонент | Призначення |
|---|---|---|
| Ядро | `netlink`, `socket` | Низькорівневий API мережі |
| Утиліти | `ip` (iproute2) | Керування інтерфейсами, маршрутами, ARP |
| Конфігурація | Netplan + NetworkManager | Декларативне налаштування мережі |
| Сервіси | `systemd-networkd`, `NetworkManager` | Застосування конфігурації |
| DNS | `systemd-resolved` | Розв'язування імен |

### 1.2 Команда `ip` — основний інструмент

Команда `ip` з пакету **iproute2** замінила застарілі `ifconfig`, `route`, `arp`.

#### Перегляд інтерфейсів

```bash
# Усі інтерфейси з адресами
ip address show
ip a                        # скорочено

# Конкретний інтерфейс
ip a show eth0

# Тільки IPv4
ip -4 a

# Тільки IPv6
ip -6 a
```

#### Управління інтерфейсами

```bash
# Увімкнути / вимкнути інтерфейс
ip link set eth0 up
ip link set eth0 down

# Встановити MAC-адресу
ip link set eth0 address 02:11:22:33:44:55

# Переглянути стан усіх інтерфейсів (коротко)
ip link show
```

#### Тимчасове призначення IP-адреси

```bash
# Додати адресу
sudo ip address add 192.168.177.101/24 dev eth0

# Видалити адресу
sudo ip address del 192.168.177.101/24 dev eth0
```

> **Увага:** Зміни через `ip` — тимчасові. Після перезавантаження налаштування скинуться. Для постійних змін використовуйте Netplan.

#### Таблиця маршрутизації

```bash
# Переглянути маршрути
ip route show
ip r                        # скорочено

# Переглянути маршрут до конкретного хоста
ip route get 8.8.8.8

# Додати маршрут
sudo ip route add 10.0.0.0/8 via 192.168.177.1

# Видалити маршрут
sudo ip route del 192.168.100.0/24

# Встановити / замінити шлюз за замовчуванням
sudo ip route replace default via 192.168.177.254
```

#### ARP-таблиця (сусіди)

```bash
# Переглянути ARP-кеш
ip neighbour show
ip n

# Очистити ARP-кеш
sudo ip neighbour flush dev eth0
```

### 1.3 Netplan — декларативна конфігурація мережі

**Netplan** — система конфігурації мережі в Ubuntu, що використовує YAML-файли у `/etc/netplan/`.

#### Структура конфігурації

```bash
# Переглянути наявні конфігурації
ls /etc/netplan/

# Типово: 00-installer-config.yaml або 50-cloud-init.yaml
cat /etc/netplan/00-installer-config.yaml
```

#### Приклад: статична IP-адреса

Файл `/etc/netplan/00-installer-config.yaml`:

```yaml
network:
  version: 2
  ethernets:
    eth0:
      dhcp4: false
      addresses:
        - 192.168.177.101/24
      routes:
        - to: default
          via: 192.168.177.254
      nameservers:
        addresses:
          - 8.8.8.8
          - 1.1.1.1
```

> **Чому `/24`, а не просто IP-адреса?**
> Запис `192.168.177.101/24` — це **CIDR-нотація**: одна адреса + розмір мережі до якої вона належить.
> Маска `/24` (= `255.255.255.0`) потрібна ядру Linux, щоб визначити:
>
> | Питання | Відповідь |
> |---|---|
> | Яка мережа "своя"? | `192.168.177.0 – 192.168.177.255` |
> | Куди слати пакет напряму (без шлюзу)? | До будь-кого в `192.168.177.x` |
> | Куди слати через шлюз? | До всіх інших мереж |
>
> Без `/24` ядро не може автоматично побудувати маршрут до локальної мережі.
> `192.168.177.101/24` — це сучасний еквівалент класичного запису IP `192.168.177.101` + маска `255.255.255.0`.

#### Приклад: DHCP

```yaml
network:
  version: 2
  ethernets:
    eth0:
      dhcp4: true
```

#### Застосування конфігурації

```bash
# Перевірити синтаксис без застосування
sudo netplan generate

# Застосувати (з можливістю відкату через 120 секунд)
sudo netplan try

# Застосувати без відкату
sudo netplan apply
```

> **Права доступу:** Файли Netplan повинні мати права `600`, інакше виникне попередження:
> ```bash
> sudo chmod 600 /etc/netplan/00-installer-config.yaml
> ```

### 1.4 Перевірка мережевого з'єднання

```bash
# ICMP-пінг (4 пакети)
ping -c 4 192.168.177.102

# Пінг з розміром пакету 1400 байт (тест MTU)
ping -c 4 -s 1400 192.168.177.102

# Трасування маршруту
traceroute 8.8.8.8

# Або через mtr (інтерактивно)
mtr 8.8.8.8
```

### 1.5 DNS та розв'язування імен

#### Файл `/etc/hosts`

Локальна таблиця відповідності імен та IP-адрес — перевіряється **до** DNS:

```bash
cat /etc/hosts
```

```
127.0.0.1   localhost
127.0.1.1   myserver

```

```bash

```

#### Перевірка DNS

```bash

resolvectl query google.com

# Або через dig
dig google.com

# Короткий вивід
dig +short google.com

# Зворотний DNS (IP → ім'я)

```

### 1.6 Мережеві утиліти діагностики

| Утиліта | Команда встановлення | Призначення |

## 2. Ознайомлення з OpenSSH

### 2.1 Що таке SSH

**SSH (Secure Shell)** — криптографічний мережевий протокол для безпечного віддаленого управління системами. Замінив незахищені протоколи Telnet і rsh.

| Характеристика | Значення |
|---|---|
| Порт за замовчуванням | TCP 22 |
| Алгоритми шифрування | AES-256, ChaCha20 |
| Автентифікація | пароль, ключ, сертифікат |
| Реалізація | OpenSSH (клієнт + сервер) |

**Компоненти OpenSSH:**

| Компонент | Пакет | Призначення |
|---|---|---|
| `sshd` | `openssh-server` | SSH-сервер (демон) |
| `ssh` | `openssh-client` | SSH-клієнт |
| `ssh-keygen` | `openssh-client` | Генерація ключів |
| `ssh-copy-id` | `openssh-client` | Копіювання ключа на сервер |
| `ssh-agent` | `openssh-client` | Агент зберігання ключів |

### 2.2 Встановлення та запуск SSH-сервера

```bash
# Встановити сервер (на VM1 — server)
sudo apt update
sudo apt install -y openssh-server

# Перевірити статус
sudo systemctl status ssh

# Увімкнути автозапуск
sudo systemctl enable ssh

# Запустити / зупинити / перезапустити
sudo systemctl start ssh
sudo systemctl stop ssh
sudo systemctl restart ssh

# Перевірити, що порт 22 прослуховується
ss -tlnp | grep :22
```

### 2.3 Підключення до SSH-сервера

З **VM2 (client)** підключаємось до **VM1 (server)**:

```bash
# Базове підключення
ssh username@192.168.177.101

# Підключення з вказаним портом
ssh -p 22 username@192.168.177.101

# Підключення з вказаним ключем
ssh -i ~/.ssh/id_ed25519 username@192.168.177.101

# Виконати команду без інтерактивної сесії
ssh username@192.168.177.101 "df -h"

# Переглянути версію SSH-сервера
ssh -v username@192.168.177.101 2>&1 | grep "Server version"
```

### 2.4 Аутентифікація за ключами

Аутентифікація за ключами безпечніша за паролі: приватний ключ ніколи не передається по мережі.

#### Схема роботи

```
[client]                          [server]
  │                                   │
  │── має: приватний ключ (~/.ssh/)   │
  │                                   │── зберігає: публічний ключ
  │                                   │   (~/.ssh/authorized_keys)
  │                                   │
  │──── підключення ────────────────► │
  │◄─── challenge (випадкові дані) ── │
  │── підписує challenge приватним ключем
  │──── підпис ─────────────────────► │
  │                  перевіряє підпис публічним ключем
  │◄─── дозвіл на вхід ───────────── │
```

#### Генерація ключової пари

```bash
# На VM2 (client) — генерувати ключ Ed25519 (рекомендовано)
ssh-keygen -t ed25519 -C "student@tsa243"

# Або RSA 4096 (для сумісності зі старими системами)
ssh-keygen -t rsa -b 4096 -C "student@tsa243"

# Файли, що створюються:
# ~/.ssh/id_ed25519       — приватний ключ (зберігати в таємниці!)
# ~/.ssh/id_ed25519.pub   — публічний ключ (можна передавати)
```

```bash
# Переглянути публічний ключ
cat ~/.ssh/id_ed25519.pub
```

#### Копіювання публічного ключа на сервер

```bash
# Спосіб 1: ssh-copy-id (найпростіше)
ssh-copy-id -i ~/.ssh/id_ed25519.pub username@192.168.177.101

# Спосіб 2: вручну
cat ~/.ssh/id_ed25519.pub | ssh username@192.168.177.101 \
  "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

#### Перевірка входу без пароля

```bash
# Після копіювання ключа — підключитись без пароля
ssh username@192.168.177.101

# Якщо не спрацьовує — перевірити права
ls -la ~/.ssh/
# ~/.ssh/           має бути 700
# authorized_keys   має бути 600
```

### 2.5 Конфігурація SSH-клієнта

Файл `~/.ssh/config` дозволяє задати псевдоніми та параметри для кожного хоста:

```bash
nano ~/.ssh/config
```

```
# Загальні параметри для всіх хостів
Host *
    ServerAliveInterval 60
    ServerAliveCountMax 3

# Псевдонім для сервера в Proxmox
Host server
    HostName 192.168.177.101
    User student
    IdentityFile ~/.ssh/id_ed25519
    Port 22

# Ще один хост
Host backup-server
    HostName 192.168.177.103
    User backupadmin
    IdentityFile ~/.ssh/id_backup
```

```bash
# Тепер замість ssh student@192.168.177.101 можна писати:
ssh server
```

### 2.6 Конфігурація SSH-сервера (sshd)

Головний файл конфігурації сервера: `/etc/ssh/sshd_config`

```bash
sudo nano /etc/ssh/sshd_config
```

#### Важливі параметри

```
# Порт прослуховування
Port 22

# Дозволити вхід root (рекомендовано: no)
PermitRootLogin no

# Дозволити аутентифікацію за паролем (після налаштування ключів — no)
PasswordAuthentication yes

# Дозволити аутентифікацію за ключами
PubkeyAuthentication yes

# Максимум спроб аутентифікації
MaxAuthTries 3

# Таймаут неактивної сесії (секунди)
ClientAliveInterval 300
ClientAliveCountMax 2

# Дозволений список користувачів
AllowUsers student admin
```

```bash
# Перевірити синтаксис конфігурації
sudo sshd -t

# Застосувати зміни
sudo systemctl reload ssh
```

### 2.7 SSH-тунелювання (Port Forwarding)

```bash
# Локальний тунель: перенаправити локальний порт 8080 на port 80 сервера
ssh -L 8080:localhost:80 username@192.168.177.101

# Після цього — відкрити у браузері http://localhost:8080

# Динамічний тунель (SOCKS-проксі)
ssh -D 1080 username@192.168.177.101

# Виконати у фоні (-N — не виконувати команду, -f — фонове виконання)
ssh -N -f -L 8080:localhost:80 username@192.168.177.101
```

### 2.8 Журнал подій SSH

```bash
# Переглянути журнал SSH-сервера
sudo journalctl -u ssh -n 50

# Переглянути невдалі спроби входу
sudo journalctl -u ssh | grep "Failed password"

# Переглянути успішні входи
sudo journalctl -u ssh | grep "Accepted"

# Реального часу (стежити за подіями)
sudo journalctl -u ssh -f
```

## 3. Безпечне копіювання та синхронізація файлів: SCP, Rsync

### 3.1 SCP — Secure Copy Protocol

**SCP** (`scp`) — утиліта для копіювання файлів між хостами через SSH. Проста у використанні, але не підтримує відновлення після переривання.

> **Примітка:** У сучасних системах OpenSSH рекомендує `sftp` або `rsync` замість `scp` через обмеження протоколу. Проте `scp` залишається широко вживаним.

#### Синтаксис

```
scp [опції] джерело призначення
```

Формат віддаленого шляху: `[користувач@]хост:шлях`

#### Копіювання файлів

```bash
# Локальний файл → на сервер
scp report.txt student@192.168.177.101:/home/student/

# З сервера → локально
scp student@192.168.177.101:/home/student/report.txt ./

# Між двома серверами
scp user@host1:/path/file.txt user@host2:/path/

# З вказаним SSH-ключем
scp -i ~/.ssh/id_ed25519 file.txt student@192.168.177.101:/tmp/
```

#### Копіювання директорій

```bash
# Рекурсивно (-r)
scp -r ./myproject/ student@192.168.177.101:/home/student/

# З сервера рекурсивно
scp -r student@192.168.177.101:/var/log/nginx/ ./nginx-logs/
```

#### Корисні опції SCP

| Опція | Призначення |
|---|---|
| `-r` | Рекурсивне копіювання директорій |
| `-P port` | Вказати нестандартний порт (велика P!) |
| `-i keyfile` | Вказати SSH-ключ |
| `-C` | Стиснення під час передачі |
| `-p` | Зберегти атрибути файлу (час, права) |
| `-l limit` | Обмежити швидкість (Кбіт/с) |
| `-v` | Детальний вивід (debug) |

```bash
# Копіювання з нестандартним портом та стисненням
scp -P 2222 -C largefile.tar.gz student@192.168.177.101:/backup/
```

### 3.2 Rsync — Розумна синхронізація

**Rsync** — потужна утиліта для синхронізації файлів та директорій. На відміну від `scp`, передає лише **різницю** між файлами (дельта-алгоритм), що суттєво економить трафік при повторних синхронізаціях.

#### Чому Rsync кращий за SCP для резервного копіювання

| Характеристика | SCP | Rsync |
|---|---|---|
| Передача лише змін | Ні | **Так** |
| Відновлення після переривання | Ні | **Так** (`--partial`) |
| Видалення зайвих файлів | Ні | **Так** (`--delete`) |
| Збереження прав/часу | Частково | **Так** (`-a`) |
| Прогрес передачі | Мінімальний | **Детальний** |
| Стиснення | Так | **Так** (`-z`) |

#### Синтаксис

```
rsync [опції] джерело призначення
```

#### Ключові опції

| Опція | Призначення |
|---|---|
| `-a` | Архівний режим: рекурсія + права + час + символічні посилання |
| `-v` | Детальний вивід |
| `-z` | Стиснення під час передачі |
| `-P` | Прогрес + збереження часткових файлів (`--progress --partial`) |
| `-n` або `--dry-run` | Симуляція без реальних змін |
| `--delete` | Видалити файли у призначенні, яких немає у джерелі |
| `--exclude` | Виключити файли/директорії за шаблоном |
| `--include` | Включити файли за шаблоном |
| `--bwlimit=KB` | Обмежити швидкість (Кбайт/с) |
| `-e` | Вказати транспорт (наприклад SSH з параметрами) |
| `--checksum` | Порівнювати за хешем, а не часом/розміром |

#### Локальна синхронізація

```bash
# Синхронізувати дві директорії на одній системі
rsync -av /home/student/docs/ /mnt/backup/docs/

# Важливо: слеш після джерела!
# /docs/  — синхронізувати вміст директорії
# /docs   — синхронізувати саму директорію (включаючи її)
```

#### Синхронізація по SSH

```bash
# Локально → на сервер
rsync -avzP ./myproject/ student@192.168.177.101:/home/student/myproject/

# З сервера → локально
rsync -avzP student@192.168.177.101:/var/www/html/ ./website-backup/

# З нестандартним SSH-портом
rsync -avzP -e "ssh -p 2222" ./data/ student@192.168.177.101:/backup/
```

#### Виключення файлів та директорій

```bash
# Виключити одну директорію
rsync -avz --exclude='.git' ./project/ student@192.168.177.101:/backup/project/

# Виключити кілька
rsync -avz \
  --exclude='.git' \
  --exclude='node_modules/' \
  --exclude='*.log' \
  ./project/ student@192.168.177.101:/backup/project/

# Виключити за файлом .rsync-exclude
rsync -avz --exclude-from='.rsync-exclude' ./project/ student@192.168.177.101:/backup/
```

Файл `.rsync-exclude`:
```
.git/
node_modules/
*.log
*.tmp
__pycache__/
```

#### Дзеркальне копіювання (з видаленням)

```bash
# Видалити файли у призначенні, яких немає у джерелі
rsync -avz --delete ./website/ student@192.168.177.101:/var/www/html/

# ОБЕРЕЖНО: --delete видаляє файли безповоротно!
# Завжди спочатку запускати з --dry-run
rsync -avzn --delete ./website/ student@192.168.177.101:/var/www/html/
```

#### Практичний приклад: скрипт резервного копіювання

```bash
#!/bin/bash
# backup.sh — резервне копіювання на віддалений сервер

SOURCE="/home/student/projects/"
DEST="student@192.168.177.101:/backup/$(date +%Y-%m-%d)/"
LOG="/var/log/backup.log"

echo "[$(date)] Початок резервного копіювання" >> "$LOG"

rsync -avzP \
  --exclude='.git' \
  --exclude='node_modules/' \
  --exclude='*.tmp' \
  --delete \
  -e "ssh -i /home/student/.ssh/id_ed25519" \
  "$SOURCE" "$DEST" >> "$LOG" 2>&1

if [ $? -eq 0 ]; then
  echo "[$(date)] Резервне копіювання завершено успішно" >> "$LOG"
else
  echo "[$(date)] ПОМИЛКА резервного копіювання!" >> "$LOG"
fi
```

### 3.3 SFTP — інтерактивна передача файлів

**SFTP (SSH File Transfer Protocol)** — інтерактивна FTP-подібна сесія поверх SSH.

```bash
# Підключитись до SFTP-сесії
sftp student@192.168.177.101

# Основні команди всередині SFTP:
sftp> ls                    # список файлів на сервері
sftp> lls                   # список локальних файлів
sftp> cd /var/log           # перейти у директорію на сервері
sftp> lcd ~/downloads       # перейти у локальну директорію
sftp> get auth.log          # завантажити файл
sftp> get -r nginx/         # завантажити директорію
sftp> put report.pdf        # вивантажити файл
sftp> put -r myproject/     # вивантажити директорію
sftp> mkdir backup          # створити директорію на сервері
sftp> rm oldfile.txt        # видалити файл на сервері
sftp> bye                   # вийти
```

## Типові задачі та команди

### Швидка довідка: від нуля до SSH-з'єднання за ключами

```bash
# 1. На сервері (VM1): встановити і запустити SSH
sudo apt install -y openssh-server
sudo systemctl enable --now ssh

# 2. На клієнті (VM2): згенерувати ключ
ssh-keygen -t ed25519 -C "student"

# 3. На клієнті: скопіювати публічний ключ на сервер
ssh-copy-id student@192.168.177.101

# 4. Перевірити вхід без пароля
ssh student@192.168.177.101

# 5. Копіювання файлу на сервер
scp myfile.txt student@192.168.177.101:/home/student/

# 6. Синхронізація директорії
rsync -avzP ./mydir/ student@192.168.177.101:/home/student/mydir/
```

### Типові помилки та їх вирішення

| Помилка | Причина | Рішення |
|---|---|---|
| `Connection refused` | sshd не запущено або порт закрито | `sudo systemctl start ssh` |
| `Permission denied (publickey)` | Ключ не скопійовано або невірні права | `ssh-copy-id`, перевірити права `~/.ssh/` |
| `Host key verification failed` | Змінився відбиток сервера | `ssh-keygen -R 192.168.177.101` |
| `WARNING: UNPROTECTED PRIVATE KEY` | Занадто широкі права на ключ | `chmod 600 ~/.ssh/id_ed25519` |
| Netplan: `file has wrong permissions` | Файл не є `root:root 600` | `sudo chmod 600 /etc/netplan/*.yaml` |
