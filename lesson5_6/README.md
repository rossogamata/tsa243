## Підготовка до заняття

Перед початком роботи перевірте, що у вас є дві VM у Proxmox:

| VM | Роль | Початкова адреса |
|---|---|---|
| VM1 | `server` | отримує по DHCP |

Обидві VM підключені до `vmbr0`. З'ясуйте поточні IP-адреси своїх VM — вони знадобляться протягом заняття.

## 1. Мережеві налаштування

### Завдання 1.1. Дослідження мережевого інтерфейсу

**Що зробити:**

На кожній VM визначте:
- Ім'я мережевого інтерфейсу та його альтернативне ім'я (`altname`)
- Поточну IP-адресу та маску підмережі (CIDR)
- MAC-адресу інтерфейсу
- Стан інтерфейсу (`UP`/`DOWN`)
- Адресу шлюзу за замовчуванням
- Поточні DNS-сервери

Знайдіть команди, що відображають цю інформацію. Запишіть результати — вони потрібні для наступних завдань.

> **Підказка:** Розділи 1.2 та 1.5 теоретичного заняття [М5З5](../lesson5_5/README.md).

**Очікуваний результат:** ви знаєте IP-адреси обох VM, ім'я інтерфейсу, шлюз і DNS.

---

### Завдання 1.2. Налаштування статичної IP-адреси через Netplan

Зараз ваші VM отримують IP по DHCP. Переведіть **VM1** на статичну адресацію.

**Що зробити:**

1. Ознайомтесь зі структурою файлу конфігурації Netplan на VM1.
2. Зробіть резервну копію поточного файлу конфігурації.
3. Відредагуйте конфігурацію, встановивши:
   - Статичну адресу `192.168.177.101/24`
   - Шлюз за замовчуванням (той, що визначили у завданні 1.1)
   - DNS-сервери: `8.8.8.8` та `1.1.1.1`
4. Перед застосуванням перевірте синтаксис конфігурації.
5. Застосуйте конфігурацію через `netplan try` — дочекайтесь підтвердження або автоматичного відкату.
6. Перевірте, що адреса змінилась.

> **Важливо:** Файл Netplan повинен належати `root` і мати права `600`, інакше отримаєте попередження.

> **Підказка:** Розділ 1.3 теоретичного заняття [М5З5](../lesson5_5/README.md).

**Очікуваний результат:** `ip a show eth0` показує `192.168.177.101/24` без позначки `dynamic`.

---

### Завдання 1.3. Налаштування імен хостів

**Що зробити:**

1. Встановіть hostname для VM1 — `server`, для VM2 — `client`:
   ```
   sudo hostnamectl set-hostname <ім'я>
   ```
2. На кожній VM додайте записи у `/etc/hosts` так, щоб `server` розпізнавалось як `192.168.177.101`, а `client` — як IP вашої VM2.
3. Перевірте, що з VM2 можна звернутись до VM1 за іменем (без IP).

**Очікуваний результат:**
```
$ ping -c 2 server
PING server (192.168.177.101) ...
```

---

### Завдання 1.4. Перевірка маршрутизації

**Що зробити:**

1. Перегляньте таблицю маршрутизації на VM1.
2. Знайдіть у виводі: маршрут до локальної мережі (connected route) та маршрут за замовчуванням.
3. Поясніть (письмово або усно викладачу): чому маршрут до `192.168.177.0/24` з'явився автоматично після налаштування адреси?
4. Перевірте, чи є доступ до зовнішньої мережі: виконайте пінг до `8.8.8.8` та до `google.com`.
   - Якщо пінг по IP працює, а по імені — ні: яка підсистема відповідальна і де шукати причину?

> **Підказка:** Розділи 1.4 та 1.5 теоретичного заняття [М5З5](../lesson5_5/README.md).

## 2. Сканування та діагностика мережі

### Завдання 2.1. Перегляд відкритих портів і з'єднань

**Що зробити:**

На VM1:
1. Знайдіть команду, що показує всі TCP-порти у стані `LISTEN`.
2. Знайдіть команду, що показує всі активні UDP-з'єднання.
3. Визначте: які процеси прослуховують мережеві порти? Яка команда дає цю інформацію?
4. Після встановлення SSH (завдання 2.2) — порівняйте вивід до і після.

> **Підказка:** Розділ 1.6 теоретичного заняття [М5З5](../lesson5_5/README.md). Команда `ss`.

**Очікуваний результат:** ви вмієте читати вивід `ss` та ідентифікувати, який процес прослуховує кожен порт.

---

### Завдання 2.2. Встановлення та перевірка SSH-сервера

**Що зробити:**

На VM1 (server):
1. Перевірте, чи встановлений та запущений SSH-сервер. Знайдіть команди для перевірки статусу служби.
2. Якщо не встановлений — встановіть та запустіть.
3. Налаштуйте автоматичний запуск SSH при завантаженні системи.
4. Переконайтесь, що порт 22 прослуховується (скористайтесь інструментом з завдання 2.1).

На VM2 (client):
5. Спробуйте підключитись до VM1 по SSH (за IP або за іменем `server`).
6. Після успішного підключення — виконайте кілька команд на VM1 через SSH-сесію: перегляньте hostname, uptime, список файлів у `/etc`.
7. Вийдіть із SSH-сесії.

> **Підказка:** Розділи 2.1–2.3 теоретичного заняття [М5З5](../lesson5_5/README.md).

**Очікуваний результат:** підключення `ssh student@server` з VM2 відкриває сесію на VM1.

---

### Завдання 2.3. Діагностика з'єднання між VM

**Що зробити:**

З VM2 виконайте повну діагностику з'єднання з VM1:

1. **ICMP:** перевірте доступність хосту. Скільки пакетів передано, скільки отримано, який відсоток втрат?
2. **Маршрут:** визначте маршрут до VM1. Скільки хопів між VM2 і VM1?
3. **Порт:** перевірте доступність конкретного порту на VM1 без підключення (тільки тест доступності).
4. **Захоплення трафіку:** на VM1 запустіть захоплення пакетів на мережевому інтерфейсі, обмежте фільтром лише ICMP-трафік. Потім з VM2 виконайте пінг до VM1. Що відобразилося у захопленні? Завершіть захоплення.

> **Підказка:** Розділ 1.6 теоретичного заняття [М5З5](../lesson5_5/README.md). Утиліти: `ping`, `traceroute`, `nc`, `tcpdump`.

---

### Завдання 2.4. Сканування мережі з nmap

**Що зробити:**

1. Встановіть `nmap` на VM2.
2. Виконайте базове сканування VM1:
   - Визначте, які TCP-порти відкриті на VM1.
   - Спробуйте визначити версії сервісів на відкритих портах.
   - Визначте операційну систему VM1 (може вимагати `sudo`).
3. Виконайте сканування всієї підмережі `192.168.177.0/24` методом ping-scan (лише виявлення хостів, без сканування портів). Скільки хостів відповіло?
4. **Питання для роздумів:** чому деякі хости можуть не відповідати на ping-scan, навіть якщо вони увімкнені?

> **Важливо:** `nmap` — діагностичний інструмент. Використовуйте його лише в мережах, де маєте відповідний дозвіл.

> **Підказка:** `nmap --help` або `man nmap`. Ключові прапори: `-sV`, `-O`, `-sn`.

**Очікуваний результат:** ви бачите відкриті порти VM1 та можете інтерпретувати вивід nmap.

---

### Завдання 2.5. Аналіз журналу SSH

**Що зробити:**

На VM1:
1. Знайдіть у системному журналі записи про підключення, які ви виконували у завданні 2.2.
2. Визначте: яка IP-адреса клієнта зафіксована у журналі?
3. Знайдіть запис про успішну аутентифікацію. Яким методом вона виконана (пароль чи ключ)?
4. Виконайте навмисно **невдалу** спробу підключення з VM2 (неправильний пароль). Знайдіть відповідний запис у журналі VM1.

> **Підказка:** Розділ 2.8 теоретичного заняття [М5З5](../lesson5_5/README.md). Команда `journalctl`.

## Контрольні запитання

Після виконання завдань підготуйтесь відповісти на запитання:

1. У чому різниця між `ip a` та `ip link`? Яку інформацію додатково надає перша команда?
2. Для чого у Netplan вказується маска підмережі (`/24`) разом з IP-адресою?
3. Що станеться, якщо застосувати `netplan apply` з помилковою адресою шлюзу? Чим `netplan try` безпечніший?
4. Яка різниця між `ss -tlnp` та `ss -tunap`? Що означає кожна буква у наборі прапорів?
5. Чому пінг до `8.8.8.8` може працювати, а `ping google.com` — ні?
6. Що фіксує `tcpdump` і для яких задач він незамінний порівняно з `nmap`?
