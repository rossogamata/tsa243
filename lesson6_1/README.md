## 1. Поняття DNS

### 1.1 Визначення

**DNS (Domain Name System)** — ієрархічна розподілена система, яка перетворює доменні імена (зрозумілі людині) на IP-адреси (зрозумілі машинам), і навпаки.

| Людина читає | Машина розуміє |
|---|---|
| `www.zsu.gov.ua` | `93.175.148.20` |
| `mail.mil.gov.ua` | `195.78.68.5` |
| `google.com` | `142.250.74.46` |

> **Питання до аудиторії:** Що буде, якщо ввести в браузер `172.217.16.4` замість `google.com`? Чи відкриється сайт?
>
> Відповідь: Так — бо комп'ютери спілкуються саме цифрами. DNS існує виключно для зручності людини.

### 1.2 Аналогія — телефонна книга

| Телефонна книга | DNS |
|---|---|
| Ім'я абонента | Доменне ім'я (`google.com`) |
| Номер телефону | IP-адреса (`142.250.74.46`) |
| Сама книга | DNS-база даних |
| Довідкова служба | Recursive Resolver |

### 1.3 Навіщо DNS потрібен армії та держструктурам

- Керування внутрішніми ресурсами мережі (пошта, портали, бази даних)
- Розгортання польових мереж із власною DNS-інфраструктурою
- Виявлення та блокування шкідливих доменів (DNS Filtering)
- Моніторинг DNS-трафіку як індикатор компрометації

> **Приклад реального інциденту:** У 2016 році атака на DNS-провайдера Dyn паралізувала Twitter, Netflix, PayPal, Reddit на кілька годин по всій Східній Америці. Мережа була живою — але нею неможливо було користуватися.

> **Питання до аудиторії:** Якщо ваш підрозділ розгортає польову мережу без інтернету — чи потрібен власний DNS-сервер? Що станеться без нього?

## 2. Структура доменних імен

### 2.1 Ієрархія доменів

DNS має деревоподібну структуру. Читається **справа наліво**:

```
www . zsu . gov . ua .
 ↑       ↑    ↑   ↑  ↑
 |       |    |   |  Коренева зона (.) — невидима
 |       |    |   TLD — домен верхнього рівня
 |       |    Домен 2-го рівня (держсектор)
 |       Домен 3-го рівня (організація)
 Піддомен (субдомен)
```

### 2.2 Рівні ієрархії

#### Коренева зона (Root)

- Невидима крапка в кінці кожного домену
- Керується організацією **ICANN**
- 13 кореневих серверів (фізично — сотні, через anycast)
- `a.root-servers.net` ... `m.root-servers.net`

#### TLD — домени верхнього рівня

| Тип | Приклади | Призначення |
|---|---|---|
| Національні (ccTLD) | `.ua`, `.de`, `.us`, `.uk` | Країни |
| Загальні (gTLD) | `.com`, `.org`, `.net`, `.mil` | Категорії |
| Нові gTLD | `.bank`, `.army`, `.cloud` | Спеціалізовані |

#### Домени 2-го рівня

Реєструються організаціями: `google.com`, `zsu.gov.ua`, `mil.gov.ua`

#### Субдомени (3-й рівень і далі)

Створюються адміністраторами всередині організації:
`mail.mil.gov.ua`, `vpn.corp.example.com`

### 2.3 Типи DNS-записів

| Запис | Назва | Що зберігає |
|---|---|---|
| `A` | Address | Ім'я → IPv4 адреса |
| `AAAA` | IPv6 Address | Ім'я → IPv6 адреса |
| `CNAME` | Canonical Name | Псевдонім → інше ім'я |
| `MX` | Mail Exchanger | Куди доставляти пошту |
| `NS` | Name Server | Які сервери відповідають за зону |
| `TXT` | Text | Довільний текст (верифікація, SPF) |
| `PTR` | Pointer | IP → ім'я (зворотний DNS) |

**Приклад зони `zsu.gov.ua`:**

```
zsu.gov.ua.      IN  A      93.175.148.20
zsu.gov.ua.      IN  MX     10 mail.zsu.gov.ua.
www.zsu.gov.ua.  IN  CNAME  zsu.gov.ua.
mail.zsu.gov.ua. IN  A      93.175.148.21
zsu.gov.ua.      IN  NS     ns1.zsu.gov.ua.
```

> **Завдання для аудиторії (усно):** Розберіть по рівнях:
> 1. `portal.army.mil.ua`
> 2. `smtp.mail.google.com`
> 3. `ns1.cloudflare.com`

## 3. Функціонал DNS-сервера та ланцюг DNS-запиту

### 3.1 Типи DNS-серверів

| Тип | Роль |
|---|---|
| **Recursive Resolver** | Приймає запит від клієнта, шукає відповідь сам |
| **Root Server** | Знає, хто відповідає за кожен TLD |
| **TLD Server** | Знає, хто відповідає за домени в зоні `.ua`, `.com` тощо |
| **Authoritative NS** | Зберігає реальні записи конкретного домену |

### 3.2 Ланцюг DNS-запиту: від клавіатури до сервера

**Сценарій:** Курсант відкриває браузер і вводить `www.zsu.gov.ua`

---

#### Крок 1 — Кеш браузера

Браузер перевіряє власний кеш.

- Знайшов → використовує збережену IP. **Запит далі не йде.**
- Не знайшов → переходить до кроку 2.

```
[Браузер] → перевіряє кеш → немає → далі
```

> Переглянути кеш у Chrome: `chrome://net-internals/#dns`

---

#### Крок 2 — Файл `hosts`

ОС перевіряє локальний файл:

- Windows: `C:\Windows\System32\drivers\etc\hosts`
- Linux: `/etc/hosts`

Якщо є відповідний запис — використовується. **Запит далі не йде.**

```
127.0.0.1   localhost
192.168.1.1 router
```

> Саме цей файл є першою точкою атаки при DNS Spoofing на локальній машині.

---

#### Крок 3 — Запит до Recursive Resolver

ОС звертається до DNS-сервера (провайдер / `8.8.8.8` / `1.1.1.1`).

Resolver перевіряє **свій кеш**:

- Є відповідь → повертає клієнту. **Запит далі не йде.**
- Немає → починає рекурсивний пошук.

---

#### Крок 4 — Root DNS-сервер

```
Resolver → Root Server:
"Хто відповідає за зону .ua?"

Root Server → Resolver:
"Не знаю IP сайту, але TLD-сервер .ua — ось його адреса"
```

> Кореневих серверів фізично сотні (anycast), але логічно — 13. Керує ICANN.

---

#### Крок 5 — TLD-сервер `.ua`

```
Resolver → TLD Server .ua:
"Хто відповідає за gov.ua?"

TLD Server → Resolver:
"Авторитетний NS для gov.ua — ось його адреса"
```

---

#### Крок 6 — Авторитетний NS-сервер

```
Resolver → Authoritative NS gov.ua:
"Яка IP-адреса www.zsu.gov.ua?"

Authoritative NS → Resolver:
"A-запис: www.zsu.gov.ua → 93.175.148.20
 TTL: 3600 секунд"
```

Авторитетний сервер — єдиний, хто **точно знає** відповідь, бо зберігає DNS-записи цієї зони.

---

#### Крок 7 — Відповідь повертається назад

```
Authoritative NS → Resolver (кешує на TTL секунд)
Resolver → ОС
ОС → Браузер
```

---

#### Крок 8 — TCP-з'єднання з сервером

Тільки тепер браузер знає IP → встановлює TCP-з'єднання → TLS Handshake → HTTP-запит → отримує сторінку.

---

### 3.3 Зведена схема ланцюга запиту

```
[Курсант: www.zsu.gov.ua]
         ↓
   [Кеш браузера] ──є──→ готово
         ↓ немає
   [Файл hosts] ──є──→ готово
         ↓ немає
   [Recursive Resolver]
         ↓ немає в кеші
   [Root Server] → "хто за .ua?"
         ↓
   [TLD Server .ua] → "хто за gov.ua?"
         ↓
   [Authoritative NS] → "IP = 93.175.148.20"
         ↓
   [Resolver] → кешує → повертає
         ↓
   [Браузер] → TCP → TLS → HTTP → Сторінка
```

### 3.4 Ключові параметри

| Параметр | Значення |
|---|---|
| Кореневих серверів (логічно) | 13 |
| Типовий TTL | 300 – 86400 секунд |
| Час DNS-запиту (без кешу) | 20 – 120 мс |
| Час DNS-запиту (з кешу) | < 1 мс |

### 3.5 Загрози на рівні DNS

| Атака | Суть |
|---|---|
| **DNS Spoofing** | Підміна відповіді — жертва отримує хибну IP-адресу |
| **DNS Cache Poisoning** | Отруєння кешу резолвера — масова підміна для всіх клієнтів |
| **DNS Hijacking** | Зміна NS-записів домену (захоплення домену) |
| **DNS Tunneling** | Прихована передача даних через DNS-трафік |
| **DDoS на DNS** | Перевантаження DNS-серверів — відмова в обслуговуванні |

#### Методи захисту

| Метод | Призначення |
|---|---|
| **DNSSEC** | Цифровий підпис DNS-записів — захист від підміни |
| **DNS over HTTPS (DoH)** | Шифрування DNS-запитів поверх HTTPS |
| **DNS over TLS (DoT)** | Шифрування DNS-запитів поверх TLS |
| **Власний Recursive Resolver** | Не довіряти зовнішнім серверам |
| **Моніторинг DNS-трафіку** | Виявлення аномалій та індикаторів компрометації |

### 3.6 Практичні команди

```bash
# Стандартний DNS-запит
nslookup www.zsu.gov.ua

# Детальний маршрут запиту (trace)
dig +trace www.zsu.gov.ua

# Перевірка MX-записів (пошта)
dig MX gmail.com

# Перевірка NS-записів зони
dig NS gov.ua

# Зворотній DNS (IP → ім'я)
nslookup 8.8.8.8

# Короткий вивід IP
dig +short google.com

# Запит до конкретного DNS-сервера
dig @8.8.8.8 www.zsu.gov.ua
```

## Загрозова модель: DNS як вектор атаки

```
[Зловмисник]
      │
      ├── DNS Spoofing → підміна A-запису → жертва йде на хибний сервер
      │
      ├── Cache Poisoning → отруєння резолвера → всі клієнти отримують хибну IP
      │
      ├── DNS Hijacking → компрометація реєстратора → зміна NS-записів домену
      │
      ├── DNS Tunneling → ексфільтрація даних через TXT/CNAME запити
      │
      └── DDoS → флуд запитами → резолвер не відповідає → мережа недоступна
```

## Підсумок

| Тема | Ключові поняття |
|---|---|
| Поняття DNS | Перетворення імен ↔ IP, розподілена ієрархічна система |
