## 1. Написання BASH-скриптів

### Загальні вимоги до скрипту (для всіх варіантів)

Кожен скрипт повинен відповідати таким вимогам:

| Вимога | Опис |
|---|---|
| **Shebang** | Перший рядок: `#!/bin/bash` |
| **Аргументи** | Скрипт приймає аргументи з командного рядка; якщо аргументи не передані або некоректні — виводить підказку щодо використання та завершує роботу з кодом `1` |
| **Змінні** | Усі значення зберігаються у змінних з осмисленими іменами |
| **Функції** | Логіку розбито на функції (мінімум 2) |
| **Умови** | Використовуються перевірки (`if`, `case`) там, де це необхідно |
| **Цикл** | Присутній хоча б один цикл (`for`, `while`) |
| **Логування** | Результати записуються у лог-файл або через `logger` |
| **Виведення** | Виведення зрозуміле, підписане; для зведення — підсумковий рядок |

### Перевірка скрипту перед здачею

```bash
# Синтаксична перевірка (без виконання)
bash -n myscript.sh

# Трасування виконання (дуже детально)
bash -x myscript.sh [аргументи]

# Запуск
chmod +x myscript.sh
./myscript.sh [аргументи]
```

### Варіант 1. Моніторинг дискового простору

**Завдання:** Написати скрипт, що перевіряє відсоток заповненості вказаних точок монтування та попереджає при перевищенні порогу.

**Аргументи:**
- `$1` — поріг спрацювання у відсотках (наприклад: `75`)
- `$2`, `$3`, ... — точки монтування для перевірки (наприклад: `/`, `/home`, `/var`)

**Що повинен робити скрипт:**
1. Перевіряє кожну передану точку монтування за допомогою `df`.
2. Якщо заповненість перевищує поріг — виводить рядок з позначкою `[WARN]` та записує подію через `logger`.
3. Якщо заповненість у нормі — виводить рядок з позначкою `[OK]`.
4. Наприкінці виводить підсумок: скільки перевірено / скільки перевищили поріг.

**Приклад запуску:**
```
./script.sh 80 / /home /var
```

### Варіант 2. Резервна копія директорії

**Завдання:** Написати скрипт, що створює стиснений архів вказаної директорії та зберігає його у каталозі резервних копій.

**Аргументи:**
- `$1` — шлях до директорії-джерела
- `$2` — шлях до каталогу призначення (де зберігати архіви)

**Що повинен робити скрипт:**
1. Перевіряє, що директорія-джерело існує.
2. Перевіряє, що каталог призначення існує (якщо ні — повідомляє про помилку).
3. Формує ім'я архіву: `backup_<назва_директорії>_<РРРР-ММ-ДД>.tar.gz`.
4. Якщо архів з такою назвою вже існує — виводить попередження і запитує підтвердження перезапису (`y/n`).
5. Створює архів за допомогою `tar`.
6. Виводить розмір створеного архіву та записує подію через `logger`.

**Приклад запуску:**
```
./script.sh /etc/nginx /backup
```

4. Виводить загальну кількість знайдених файлів та їх сумарний розмір.
5. Зберігає звіт у файл `/tmp/large_files_<РРРРММДД>.txt`.


### Варіант 6. Очищення застарілих лог-файлів

**Завдання:** Написати скрипт, що знаходить і видаляє файли `.log` у вказаній директорії, старіші за задану кількість днів.

**Аргументи:**
- `$1` — шлях до директорії
- `$2` — вік файлів у днях (видаляти файли, старіші за це значення)
- `$3` (необов'язковий) — прапор `-d` для реального видалення (без нього — режим перегляду без видалення)

**Що повинен робити скрипт:**
1. Знаходить файли `.log` старіші за `$2` днів через `find`.
2. Без прапора `-d` виводить список файлів, які **були б** видалені (dry-run).
3. З прапором `-d` видаляє їх, підраховує кількість та загальний розмір видаленого.
4. Записує у лог-файл `/tmp/cleanup.log` дату, директорію та результат операції.

**Приклад запуску:**
```
./script.sh /var/log 30        # перегляд
./script.sh /var/log 30 -d     # реальне видалення
```

### Варіант 11. Моніторинг конкретного процесу

## 2. Налаштування syslog-сервера

### 2.1 Концепція централізованого логування

У виробничих середовищах логи з **багатьох серверів** збираються в єдиному місці — **централізованому syslog-сервері**. Це дозволяє:
- Аналізувати події з усієї інфраструктури в одному місці
- Зберігати логи навіть після виходу з ладу клієнтського сервера
- Виявляти кореляції між подіями на різних вузлах

```
Клієнт A (веб-сервер)  ──┐
Клієнт B (БД-сервер)   ──┤──→  Syslog-сервер  →  /var/log/remote/
Клієнт C (поштовий)    ──┘     (rsyslog TCP/UDP 514)
```

**Протоколи передачі:**
- **UDP 514** — швидко, але без гарантії доставки; підходить для нагромадженої інформації
- **TCP 514** — надійна доставка з підтвердженням; рекомендовано для критичних логів

---

### 2.2 Налаштування rsyslog-сервера (приймач)

```bash
# Встановити rsyslog (зазвичай вже встановлено)
sudo apt install rsyslog -y

# Відкрити конфігурацію
sudo nano /etc/rsyslog.conf
```

Знайти та розкоментувати секцію `MODULES` для прийому повідомлень:

```
# /etc/rsyslog.conf — на СЕРВЕРІ

###############
#### MODULES ####
###############

# Прийом по UDP (розкоментувати обидва рядки)
module(load="imudp")
input(type="imudp" port="514")

# Прийом по TCP (розкоментувати обидва рядки)
module(load="imtcp")
input(type="imtcp" port="514")
```

Додати правило для збереження отриманих логів у окрему директорію:

```
# Зберігати логи від віддалених хостів у окремі файли
# $HOSTNAME — ім'я хоста-відправника
template(name="RemoteLogs" type="string"
         string="/var/log/remote/%HOSTNAME%/%PROGRAMNAME%.log")

# Усі повідомлення від не-localhost — у шаблон RemoteLogs
if $fromhost-ip != "127.0.0.1" then ?RemoteLogs
& stop
```

```bash
# Створити директорію для логів та встановити права
sudo mkdir -p /var/log/remote
sudo chown syslog:adm /var/log/remote

# Перезапустити rsyslog
sudo systemctl restart rsyslog

# Перевірити, що порт відкрито
sudo ss -ulnp | grep 514    # UDP
sudo ss -tlnp | grep 514    # TCP
```

### 2.3 Налаштування клієнта (відправник)

На **клієнтській** машині додати правило пересилання в `/etc/rsyslog.conf` або окремий файл:

```bash
sudo nano /etc/rsyslog.d/99-remote.conf
```

```
# /etc/rsyslog.d/99-remote.conf — на КЛІЄНТІ

# Надсилати всі повідомлення на сервер по UDP
*.* @192.168.1.100:514

# Надсилати всі повідомлення на сервер по TCP (надійніше)
*.* @@192.168.1.100:514

# Надсилати тільки err і вище по TCP
*.err @@192.168.1.100:514

# Зберегти локальну копію навіть при недоступності сервера
# (буферизація — queue)
*.* action(type="omfwd"
           target="192.168.1.100"
           port="514"
           protocol="tcp"
           action.resumeRetryCount="100"
           queue.type="linkedList"
           queue.size="10000")
```

```bash
# Перезапустити rsyslog на клієнті
sudo systemctl restart rsyslog
```

### 2.5 Перевірка з'єднання при проблемах


### 2.6 Практичне завдання по питанню 2

Налаштувати передачу логів між двома системами (або двома WSL-сесіями на одній машині, використовуючи `127.0.0.1`):

1. Налаштувати rsyslog на прийом по UDP/TCP.
2. Налаштувати клієнт на надсилання всіх логів на сервер.
3. Відправити тестове повідомлення через `logger` та переконатися, що воно з'явилося у `/var/log/remote/`.
4. Налаштувати шаблон `logrotate` для директорії `/var/log/remote/` — ротація щотижня, зберігати 4 тижні.

## Шпаргалка заняття

```bash
# ═══ BASH-СКРИПТИ ══════════════════════════════════════════
chmod +x script.sh && ./script.sh      # запустити скрипт
bash -n script.sh                       # перевірка синтаксису
bash -x script.sh                       # трасування виконання
echo "Аргументи: $# штук: $@"           # кількість та список аргументів
if [ "$#" -lt 2 ]; then echo "Usage..."; exit 1; fi  # перевірка аргументів
VAR=$(command)                          # результат команди у змінну
[ -f "$1" ] || { echo "Не файл"; exit 1; }  # перевірка файлу

# ═══ СИСТЕМНА ІНФОРМАЦІЯ ══════════════════════════════════
df -h /                                 # місце на кореневому розділі
free -m                                 # пам'ять у МБ
cat /proc/loadavg                       # load average
nproc                                   # кількість ядер
ps aux --sort=-%cpu | head -6           # топ-5 за CPU
ps aux --sort=-%mem | head -6           # топ-5 за RAM

# ═══ RSYSLOG ══════════════════════════════════════════════
sudo rsyslogd -N1                       # перевірка синтаксису конфігурації
sudo systemctl restart rsyslog          # перезапустити rsyslog
sudo ss -ulnp | grep :514               # UDP порт 514
sudo ss -tlnp | grep :514               # TCP порт 514
logger -t TAG "повідомлення"            # відправити у syslog
tail -f /var/log/remote/HOST/APP.log    # стежити за логами клієнта
```
